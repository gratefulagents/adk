# Category trace storage and exporter ownership

## Store

`adk::tracestore` is available with `observability`. It is separate from the
native ordered `observability::FilesystemTraceStore`; that store's schema-1
`events.jsonl` is not relabeled as a Go-compatible trace.

The new `TraceStore` trait and Linux `FilesystemTraceStore` expose the pinned SDK
category storage surface:

| SDK | Rust |
| --- | --- |
| `NewFilesystemTraceStore` | `FilesystemTraceStore::new` |
| `CreateRunDir`, `RunDir` | `create_run_dir`, `run_dir` |
| `AppendTrace` | `append_trace` |
| `WriteFile`, `WriteScore` | `write_file`, `write_score` |
| `ListRuns` | `list_runs` with candidate and timestamp filters |
| `UpdateMetadataMode`, `UpdateMetadataFinishedAt` | corresponding snake-case methods |
| `Close` | idempotent `close`, also descriptor ownership on drop |

Storage is `{root}/traces/{run-id}` with `metadata.json`, `score.json`, arbitrary
relative artifacts, and `<category>.jsonl`. Once the active file is full it moves
to the first free `.001`–`.004` slot; appends continue in the active file.
Reopening a store preserves category files and quotas. Creating an existing run
replaces its metadata, matching the reference, rather than deleting its traces.

Defaults: 1 MiB including a terminal newline per event, 64 MiB per append chunk,
four rotations, and 16 MiB per artifact. Quota failures have distinguishable
`StoreError` variants. Metadata/artifact replacement is an fsynced private
same-directory temporary file plus rename and directory fsync. Appending syncs
the file, and syncs the directory when creating or rotating a chunk.

The Linux backend uses `openat2` with `BENEATH`, `NO_SYMLINKS`, and
`NO_MAGICLINKS`; there is no insecure syscall fallback. Existing root symlinks
are resolved once, then directory descriptors pin the trusted root. Run paths
are checked against the pinned inode before returning their named path.
Directories are 0700 and newly created files 0600. Hardlinked append targets are
rotated rather than written through. Symlink artifacts are replaced, never
followed. Hosts must trust the owner of the root: this does not isolate mutually
hostile processes running under the same UID or coordinate multiple simultaneous
store owners. Linux with `openat2` is the supported mutation target, also the
limit imposed by the pinned Go implementation.

`RunMetadata`, `RunFilter`, `Score` and `ScoreMetrics` preserve field names and
zero timestamp defaults. Timestamps are typed RFC3339 `chrono::DateTime` values;
filter comparisons compare instants, not textual offsets. Scores reject
nonfinite metrics. `Score` is a persistence document, not an evaluation adapter;
no evaluation or Terminal-Bench execution is added.

### Independent reference

`fixtures/tracestore/sdk-store.json` is generated by
`scripts/trace-reference/main.go` against the authoritative SDK revision
`1dc92b73900fac74dc357a938e4b5eee6392b418` (GPL-3.0-only). Run:

```sh
python3 scripts/trace-reference/check.py
cargo test --locked -p adk --features observability --test tracestore
```

The checker rejects a dirty or incorrectly pinned SDK checkout and invokes the
strict immutable-baseline validator. The Rust regression compares metadata,
score, category bytes and artifact bytes independently; JSON object order and
numeric spelling are not significant for document comparisons.

This does **not** yet implement the Go `TraceWriter` hook/span conversion,
schema-2 generation snapshots, instruction artifacts or writer health. A schema
constant and compatible store are not evidence that those producers exist.

## Exporters

`adk::telemetry::Telemetry` is available with `otel`:

- `new(service_name)` reads `OTEL_EXPORTER_OTLP_ENDPOINT`.
- `with_endpoint(service_name, endpoint)` gives a nonblank explicit endpoint
  precedence over that environment variable. Blank values fall back to stdout.
- Schemeless and `http://` endpoints use plaintext gRPC; `https://` uses TLS with
  native certificate roots. URL path suffixes are removed, matching the SDK.
- The SDK provider batches every five seconds, uses instrumentation scope
  `gratefulagents/agent`, and sets the service resource with schema URL 1.26.0.
- `with_exporter` accepts host-supplied exporters; `bridge` connects existing
  observation pipelines, and `force_flush`/`shutdown` expose delivery errors.
- `install_global` is explicit. Construction does not replace a process-wide
  provider behind an embedding host's back.

Create an OTLP exporter inside a Tokio runtime. Keep that runtime alive while
exporting; on a single-thread runtime, perform blocking flush/shutdown from
`spawn_blocking` so the transport can make progress. End run pipelines before
shutting down the provider. Offline construction is not collector-delivery
verification. Stdout uses the maintained Rust exporter's human-readable format,
not Go's pretty-printed JSON. Automatic global installation, complete Go span
attributes and trace-ID callbacks remain unimplemented compatibility obligations.

Dependency research: `opentelemetry-otlp` **0.31.1** and
`opentelemetry-stdout` **0.31.0** declare **Apache-2.0**, Rust **1.75.0** in the
retrieved crate manifests. Exact registry checksums are retained in Cargo.lock.
Sources/API references:

- <https://docs.rs/opentelemetry-otlp/0.31.1/opentelemetry_otlp/>
- <https://docs.rs/opentelemetry-stdout/0.31.0/opentelemetry_stdout/>
- <https://github.com/open-telemetry/opentelemetry-rust>

Adopted: real SDK batch processors and gRPC transport/TLS. Rejected: handwritten
OTLP transport, implicit global ownership, and treating exporter construction as
proof that credentials, certificates, network routing or a collector work.
