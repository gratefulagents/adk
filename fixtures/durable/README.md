# Durable Go compatibility fixtures

Generated by `generate.go`, importing the actual SDK `pkg/agentsdk/durable` package from the pinned checkout `repos/sdk` at commit `1dc92b73900fac74dc357a938e4b5eee6392b418`. The reference package is GPL-3.0-only; fixture data is synthetic (no credentials or production data). Generation uses fixed IDs and timestamps; test-only XOR encryption has a fixed `0x5a` key and provides no security.

Regenerate from repository root:

```sh
(cd repos/sdk && go run ../../fixtures/durable/generate.go generate ../../fixtures/durable)
```

- `v1.json`: actual Go legacy document, absent event keys/sequence, cancellation, budget, non-UTC time and an integer larger than IEEE-754 precision.
- `v1-migrated.json`: actual `durable.DecodeDocument` migration result.
- `v2.json`: `durable.EncodeDocument` with every typed boundary, cumulative budgets, explicit year-one zero times, nanosecond timestamps, raw large JSON numbers, nested values and Unicode.
- `snapshot.json`, `event.json`: exact `encoding/json` bytes for PostgreSQL BYTEA bodies.
- `filesystem.json`: the Go `{document, lease}` record layout with an expired fencing lease.
- `filesystem-encrypted.json`: Go `[]byte` base64 envelope over that whole record, including lease.
- `recovery.json`: all 15 classification/state combinations and actual `durable.RecoverEffect` decisions.

Rust tests consume these files, migrate and re-encode them, and check both structured values and safety decisions. The `ADK_TEST_GO=1` tests run `generate.go verify-document` against Rust documents and `generate.go verify` against Rust-written filesystem stores. Actual Go `Load`, `AcquireLease`, `Append`, and `ReleaseLease` continue both plaintext and encrypted records, after which Rust reads the Go writes back.

`postgres/` is an isolated test helper module. It uses the same baseline durable package and the MIT-licensed `github.com/lib/pq v1.10.9` driver (never linked into Rust). With `ADK_TEST_GO=1 ADK_TEST_POSTGRES_URL=...`, it seeds plaintext/encrypted runs using the Go PostgreSQL RunStore, Rust resumes those runs and persists outcome-unknown effects and cumulative budget changes, then Go reads, verifies and resumes Rust writes. Tests use unique test schemas, not production tables. A separate Rust integration test applies `platform-042.sql`, an unmodified copy of platform `042_sdk_durable_runs.up.sql` at `08e65c970830f05042c251bcbb46ec6a9e3719b9`, to prove existing-schema compatibility. **That SQL fixture is AGPL-3.0-only**, not SDK GPL; retain the platform attribution and `fixtures/licenses/PLATFORM-AGPL-3.0.txt`. It is test-only and is not included in the reusable library.

Go payloads are compared semantically rather than byte-for-byte because Rust normalizes time offsets to UTC and JSON object ordering/HTML escaping differs. No floating-point coercion is permitted. Go's absent and explicit-null raw JSON values are both preserved. Unknown schema/effect values intentionally fail closed rather than inherit permissive Go enum decoding.
